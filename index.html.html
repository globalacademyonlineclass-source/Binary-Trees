1 Tree concepts & terminology

Arrays and linked lists are linear: every element has at most one predecessor and one successor. A tree is a non-linear, hierarchical structure: each element may have many successors but only one predecessor. Trees model file systems, organisation charts, HTML documents, decision processes, arithmetic expressions and much more.

1.1 Formal definition

A tree is a finite set of nodes such that:

  • there is exactly one specially designated node called the root; and
  • the remaining nodes are partitioned into n ≥ 0 disjoint sets T1, T2, …, Tn, each of which is itself a tree (the subtrees of the root).

Because the subtrees are themselves trees, the definition is recursive — and that is exactly why almost every tree algorithm you will write is recursive too.

Watch out: depth is measured downwards from the root (it belongs to the node), while height is measured upwards from the leaves (it belongs to the subtree). 2 Binary trees & properties

A binary tree is a tree in which every node has at most two children, conventionally called the left child and the right child. The order matters: left and right are different, even if only one child exists.

Binary tree ≠ binary search tree. A binary tree says nothing about the values stored. A BST adds the ordering rule left < node < right — that is next lecture.

2.1 Special shapes

Full (strict / proper)

Every node has either 0 or 2 children. No node has exactly one child.

Complete

All levels are full except possibly the last, which is filled strictly left-to-right. Heaps use this shape.

Perfect

All internal nodes have 2 children and all leaves are on the same level. Contains exactly 2h+1 − 1 nodes.

Balanced

The heights of the left and right subtrees of every node differ by at most 1. Keeps height ≈ log n.

Degenerate / skewed

Every node has only one child. It is effectively a linked list — height n − 1, all operations O(n).

Our sample tree

Not full (C has one child), not complete (level 2 has a gap at C's left), not perfect. Height = 3.

Quick check on our sample tree

  • n = 7 nodes → edges = 6 ✓
  • Null links = n + 1 = 8. Count them: D(2), F(2), G(2), C's left(1), E's right(1) = 8 ✓
  • Height 3 → max possible nodes = 24 − 1 = 15. We only use 7, so there is room for 8 more.
  • Minimum height for 7 nodes = ⌊log₂ 7⌋ = 2 — our tree is not optimally balanced.

3 Representing binary trees

Two standard representations. Choose based on the shape of your tree.

Each node is an object holding the data plus two references. The tree itself is just a reference to the root. Empty subtrees are represented by null.

TreeNode.java 
/** One node of a binary tree. */
class TreeNode {
    char data;          // payload (use int, String or a generic T in general)
    TreeNode left;      // reference to the left child  (null = no child)
    TreeNode right;     // reference to the right child (null = no child)

    TreeNode(char data) {
        this.data = data;      // left and right are automatically null
    }

    boolean isLeaf() {
        return left == null && right == null;
    }
}
Why it is flexible: the linked form allocates memory only for nodes that actually exist. A tree with 7 nodes costs exactly 7 node objects — no wasted slots, no matter how skewed the shape is. The price is that each node carries two references (memory overhead) and the tree is not a contiguous block (poorer cache locality).

A binary tree can also be stored in a single array by numbering the nodes in level order and placing each node at its number. If a node sits at index i, its relatives are found by pure arithmetic — no pointers at all:

Index formulas (0-based array):
left(i) = 2i + 1  ·  right(i) = 2i + 2  ·  parent(i) = (i − 1) / 2  (integer division)

ArrayBinaryTree.java 
public class ArrayBinaryTree {
    private Integer[] tree;          // null marks an empty slot

    public ArrayBinaryTree(int capacity) {
        tree = new Integer[capacity];
    }

    /* --- index arithmetic --- */
    public int left(int i)   { return 2 * i + 1; }
    public int right(int i)  { return 2 * i + 2; }
    public int parent(int i) { return (i - 1) / 2; }   // integer division

    public void setRoot(int value)              { tree[0] = value; }
    public void setLeft(int i, int value)       { tree[left(i)]  = value; }
    public void setRight(int i, int value)      { tree[right(i)] = value; }

    /** Preorder traversal of the array form — note the base case must also
        check the array bounds, because a missing child may fall off the end. */
    public void preorder(int i) {
        if (i >= tree.length || tree[i] == null) return;
        System.out.print(tree[i] + " ");
        preorder(left(i));
        preorder(right(i));
    }
}
The cost of gaps. A skewed tree of n nodes has height n − 1, so its array needs up to 2n − 1 slots. Ten nodes in a chain would need 1023 slots! The array form is therefore only sensible for complete trees — which is precisely why heaps use it.

Rule of thumb: if the tree is complete (or nearly so), the array wins — no pointers, perfect locality, and O(1) parent lookup. Otherwise use the linked form.

4 Binary-tree traversal techniques

A traversal is a systematic way of visiting every node in the tree exactly once. Because a tree is not linear, "visit everything" is ambiguous — and each sensible order turns out to be useful for a different problem.

TraversalOrderTypical use
PreorderNode → Left → RightCopy/clone a tree, serialize, prefix expression, directory listing
InorderLeft → Node → RightSorted output from a BST, infix expression
PostorderLeft → Right → NodeDelete/free a tree, evaluate postfix expression, compute sizes/heights
Level-orderLevel 0, then level 1, …Breadth-first search, printing by level, checking completeness
Depth-first vs breadth-first. The first three are depth-first (they dive to a leaf before backtracking) and are naturally recursive. Level-order is breadth-first and needs a queue instead of a call stack.

4.2 The three depth-first orders, traced by hand

Remember the one-line rule: the position of "visit" relative to the two recursive calls decides the order.

Preorder — visit, then left, then right

A → B → D → E → G → C → F

Trace: visit A, descend left to B, descend left to D (leaf, backtrack), right to E, left to G (backtrack twice), back up to A, descend right to C, then right to F.

Inorder — left, visit, right

D → B → G → E → A → C → F

Trace: go as far left as possible (D), visit D, back to B, visit B, into E's left (G), visit G, visit E, back to A, visit A, right to C, visit C, right to F.

Postorder — left, right, then visit

D → G → E → B → F → C → A

Trace: children are always finished before their parent. The root A is visited last — which is why postorder is the order you delete a tree in.

Level-order — top to bottom, left to right

A → B → C → D → E → F → G

Trace: enqueue A; dequeue A, visit it, enqueue B and C; dequeue B, visit, enqueue D and E; … Each node enqueues its children as it is visited.

Exam tip: to find the inorder sequence quickly, "squash" the tree: read every node as if you were projecting it straight down onto a horizontal line. To find preorder, trace the outline of the tree anti-clockwise, writing a node the first time you pass its left side.

5 Implementing binary trees in Java

5.1 Recursive traversals — the canonical code

Each recursive method has exactly the same shape: base case (empty subtree → return) followed by three statements whose order defines the traversal.

BinaryTree.java (part 1 — recursive traversals) 
import java.util.*;

public class BinaryTree {

    private TreeNode root;

    public BinaryTree()              { root = null; }
    public BinaryTree(TreeNode root) { this.root = root; }
    public boolean isEmpty()         { return root == null; }

    /* ---------- public wrappers ---------- */
    public void preorder()  { preorder(root);  System.out.println(); }
    public void inorder()   { inorder(root);   System.out.println(); }
    public void postorder() { postorder(root); System.out.println(); }

    /* ---------- recursive workers ---------- */
    private void preorder(TreeNode node) {
        if (node == null) return;             // base case: empty subtree
        System.out.print(node.data + " ");    // 1. VISIT
        preorder(node.left);                  // 2. LEFT
        preorder(node.right);                 // 3. RIGHT
    }

    private void inorder(TreeNode node) {
        if (node == null) return;
        inorder(node.left);                   // 1. LEFT
        System.out.print(node.data + " ");    // 2. VISIT
        inorder(node.right);                  // 3. RIGHT
    }

    private void postorder(TreeNode node) {
        if (node == null) return;
        postorder(node.left);                 // 1. LEFT
        postorder(node.right);                // 2. RIGHT
        System.out.print(node.data + " ");    // 3. VISIT
    }
}
Why the wrapper? Users of the class should not have to know about TreeNode or pass the root themselves. The public no-argument method hides the recursion behind a clean API.

5.2 Level-order traversal

BinaryTree.java (part 2 — breadth-first) 
    /** Breadth-first traversal using a FIFO queue. */
    public void levelOrder() {
        if (root == null) return;

        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);                       // start with the root

        while (!queue.isEmpty()) {
            TreeNode node = queue.poll();        // take the front node
            System.out.print(node.data + " ");   // visit it

            if (node.left  != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
        System.out.println();
    }

    /** Level-order, one line per level — useful for visualising the shape. */
    public void levelOrderByLevel() {
        if (root == null) return;
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);

        while (!queue.isEmpty()) {
            int nodesOnThisLevel = queue.size();   // freeze the level size
            for (int i = 0; i < nodesOnThisLevel; i++) {
                TreeNode node = queue.poll();
                System.out.print(node.data + " ");
                if (node.left  != null) queue.offer(node.left);
                if (node.right != null) queue.offer(node.right);
            }
            System.out.println();                  // end of a level
        }
    }

5.3 Iterative depth-first traversals

Recursion uses the JVM call stack. When the tree is very deep, that stack can overflow (StackOverflowError), so an explicit Deque used as a stack is often preferred.

IterativeTraversals.java 
import java.util.*;

public class IterativeTraversals {

    /* ---------- PREORDER: push root, pop, print, push right then left ---------- */
    public static void preorder(TreeNode root) {
        if (root == null) return;
        Deque<TreeNode> stack = new ArrayDeque<>();
        stack.push(root);

        while (!stack.isEmpty()) {
            TreeNode node = stack.pop();
            System.out.print(node.data + " ");
            if (node.right != null) stack.push(node.right);  // right first ...
            if (node.left  != null) stack.push(node.left);   // ... so left pops first
        }
        System.out.println();
    }

    /* ---------- INORDER: slide left as far as possible, then pop & go right ---------- */
    public static void inorder(TreeNode root) {
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode current = root;

        while (current != null || !stack.isEmpty()) {
            while (current != null) {      // walk down the left spine
                stack.push(current);
                current = current.left;
            }
            current = stack.pop();         // leftmost unvisited node
            System.out.print(current.data + " ");
            current = current.right;       // then its right subtree
        }
        System.out.println();
    }

    /* ---------- POSTORDER: one stack + a "last visited" marker ---------- */
    public static void postorder(TreeNode root) {
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode current = root;
        TreeNode lastVisited = null;

        while (current != null || !stack.isEmpty()) {
            if (current != null) {
                stack.push(current);
                current = current.left;
            } else {
                TreeNode peek = stack.peek();
                if (peek.right != null && lastVisited != peek.right) {
                    current = peek.right;          // right subtree still pending
                } else {
                    System.out.print(peek.data + " ");
                    lastVisited = stack.pop();     // both subtrees done
                }
            }
        }
        System.out.println();
    }
}
Common bug: in iterative preorder, forgetting to push right before left. A stack is LIFO, so whatever you push last is popped first. Push right first to have left processed first.

5.4 Other core operations

BinaryTree.java (part 3 — operations) 
    /* ---------- height in edges (empty tree = -1, single node = 0) ---------- */
    public int height() { return height(root); }

    private int height(TreeNode node) {
        if (node == null) return -1;
        return 1 + Math.max(height(node.left), height(node.right));
    }

    /* ---------- number of nodes ---------- */
    public int size() { return size(root); }

    private int size(TreeNode node) {
        if (node == null) return 0;
        return 1 + size(node.left) + size(node.right);
    }

    /* ---------- number of leaves ---------- */
    public int countLeaves() { return countLeaves(root); }

    private int countLeaves(TreeNode node) {
        if (node == null) return 0;
        if (node.isLeaf()) return 1;
        return countLeaves(node.left) + countLeaves(node.right);
    }

    /* ---------- search (ordinary binary tree, no ordering rule) ---------- */
    public boolean contains(char key) { return contains(root, key); }

    private boolean contains(TreeNode node, char key) {
        if (node == null)         return false;
        if (node.data == key)     return true;
        return contains(node.left, key) || contains(node.right, key);
    }

    /* ---------- level-order insert: first free slot, top to bottom ---------- */
    public void insert(char value) {
        TreeNode newNode = new TreeNode(value);
        if (root == null) { root = newNode; return; }

        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            TreeNode node = queue.poll();
            if (node.left == null)  { node.left  = newNode; return; }
            if (node.right == null) { node.right = newNode; return; }
            queue.offer(node.left);
            queue.offer(node.right);
        }
    }

    /* ---------- delete the whole tree (postorder!) ---------- */
    public void clear() { clear(root); root = null; }

    private void clear(TreeNode node) {
        if (node == null) return;
        clear(node.left);        // free the left subtree
        clear(node.right);       // free the right subtree
        node.left = node.right = null;   // now it is safe to drop this node
    }
Notice the pattern. height, size and countLeaves are all postorder computations: the answer for a node depends on the answers for its children, so the children must be solved first.

5.6 Complexity summary

OperationTimeExtra spaceNotes
Any traversalO(n)O(h)Each node is visited once; h is the height (recursion depth or explicit stack size)
Level-orderO(n)O(w)w = maximum width of the tree; the queue can hold a whole level
height / size / leavesO(n)O(h)Must inspect every node
search (unordered)O(n)O(h)No ordering rule to exploit — this improves to O(h) in a BST
insert at first free slotO(n)O(w)Level-order scan
clear / delete treeO(n)O(h)Postorder — free children before the parent

h ranges from ⌊log₂ n⌋ for a balanced tree to n − 1 for a skewed one. That difference — O(log n) versus O(n) — is the entire motivation for balanced trees later in the course.
